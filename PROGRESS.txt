[PRODUCTION DRESS CRUD ISSUE & ROOT CAUSE RESOLUTION]
--------------------------------------------------------------------------------
1. Root Cause Identified:
   - Foreign Key Constraint Violation (dresses_category_id_fkey):
     * Supabase dresses table enforces category_id REFERENCES categories(id).
     * Supabase categories table contains IDs 'cat-1', 'cat-2', and 'cat-6'.
     * File DB and frontend default states used legacy category IDs ('cat-photoshoot', 'cat-reception', 'cat-bridesmaid').
     * Submitting a dress with 'cat-photoshoot' failed in Supabase with Postgres error code 23503.
   - Swallowed Supabase Errors:
     * @supabase/supabase-js functions (.insert(), .upsert(), .update(), .delete()) return { data, error } instead of throwing exceptions.
     * Route handlers wrapped calls in try-catch without checking `if (error)`, causing backend to ignore Supabase failures and report success to frontend while writing only to ephemeral file DB.
   - Serverless Persistence Disconnect:
     * Ephemeral local file DB reset across Vercel invocations, while GET endpoints read from Supabase.
     * Failed Supabase inserts resulted in newly created dresses disappearing immediately upon page refresh.

2. Solution Implemented:
   - Automatic Category ID Resolution (server/src/routes/dresses.js):
     * Added resolveValidCategoryId() helper that dynamically resolves submitted category IDs, names, or legacy slugs (e.g., 'cat-photoshoot') to valid active category IDs in Supabase ('cat-1').
   - Synchronized Category Seed Data (server/src/db.js & server/data/db.json):
     * Updated default category IDs in File DB seed data to 'cat-1', 'cat-2', 'cat-6' to align 100% with Supabase.
   - Explicit Supabase Error Checking (server/src/routes/dresses.js & server/src/routes/categories.js):
     * Added explicit `if (sbErr)` checks to log and handle Supabase operation errors across POST, PUT, PATCH, and DELETE endpoints.
   - Data & Feature Preservation:
     * Preserved all 6 existing dresses, 3 categories, customer bookings, website settings, and uploaded images intact.
